# catalog · 模型目录与能力记录

本模块属于平台控制面，对应 F01、F02 及 A01–A03。它为 routing 提供工作区允许使用的模型及可验证属性。供应商协议、实际地址、凭据解析和所有推理调用均在独立的 [gateway](../gateway/README.md) 中。目录在 SQLite 中保留每个端点版本。

| 操作 | 输入与输出 | 校验 |
|---|---|---|
| 登记模型 | 网关实例、端点别名、网关配置 ETag、实际模型身份、价格、上下文、能力和数据去向 → 不可变目录版本 | 两个别名可能指向同一模型；未经核实的身份不可充作第二个独立模型 |
| 验证能力 | 已批准的探测任务和版本 → 带时间、检查方法与证据的结果 | 列出模型只证明别名已配置；需产生推理用量的探测同样通过 runs 预留，再调用网关 |
| 提供快照 | 工作区和版本 → 允许端点、偏好与约束；使用唯一端点 ID 排序 | 禁用端点立即阻止新派发；已完成决策仍能按旧版本查询 |

安装不登记可调用模型或自动填入示例价目。管理员自行接入端点，设置币种与输入/输出单价，再向业务工作空间授权。普通任务使用获授权模型执行，模型用量按派发版本的价格与实际回执 token 统计。历史价格、未知用量和币种分列见[任务与用量](../../../docs/11-任务执行与模型用量.md)。

平台目录只需要访问网关的客户端凭据引用；供应商密钥由网关进程独占。配置者应先核实网关配置及该版本的端点去向，再登记版本。网关配置变化后重新核验，旧快照的派发收到 412 时应重新路由。详见[网关设计](../../../docs/07-Gateway详细设计.md)。

平台配置中的 `gateways` 使用固定网关 ID、服务根 URL 和可选的客户端令牌环境变量名。登记端点时提交 `gateway_id`、`endpoint_alias`、带双引号的 `gateway_etag` 和路由快照字段。配置者核实身份后设置 `identity_verified=true`。对网关地址或凭据引用的更改会停用旧绑定，需确认配置后重新登记。连通探针检查别名和 ETag，并返回新版网关声明的每次输出上限。管理员可将该值填入高级模型设置的“端点输出 token 上限”（`max_output_tokens`），让离线路由按较低上限估价和预留。旧目录缺少该字段时沿用任务上限估价；新版网关仍会按实际端点限额收紧请求。使用旧网关且限额低于任务上限时，须在平台登记实际限额。
