# audit · 可验证审计与资源历史

审计记录、业务写入、资源修订和幂等结果共享调用者事务。后台运行事件由 storage 自动追加审计记录，包含运行、事件序号、触发账号及上下文证据引用。平台资源和端点的每次修订另外保留不可原地修改的脱敏快照。

交付作业保留排队、开始、完成、失败、过期和重启中断的证据，包含原始请求账号、请求关联 ID、节点世代、需求版本、候选、冻结验收套件、输入产物及源文件摘要。结果在作业表持久化，同时以脱敏结果和摘要进入审计链。需求修订、意见处置、基线批准和接纳记录前后状态，模型答复导入单独注明模型身份、原工件摘要、解析内容与目标版本，后台执行器和人工签署的身份分别记录。

`record(db, actor, action, resource, ...)` 接受操作者、动作、对象、结果、项目、运行、关联 ID 和前后状态。凭据字段及已知密钥格式会被剔除，配置中的模型输出上限等计数保留。成员证据保存角色、启用状态及凭据轮换动作，密码、盐和会话原值不进入审计。

记录按全局序号构成 SHA-256 哈希链，SQLite 触发器拒绝对审计条目及资源历史的更新、删除。独立链头保存账本标识、最后序号和摘要。`verify(db)` 检查序号、前向关联、每条摘要、链头，以及资源历史与对应审计条目的摘要。平台当前资源、端点版本、成员可审计字段和交付作业结果也会与审计证据交叉核对。密码哈希、盐和会话原值不参与公开审计快照。数据库管理员仍可更改数据库文件和链头，独立保管导出的锚点才能对照此类重写。

`export_bundle(db, filters)` 输出完整证明链、锚点、核验结果和筛选选中的序号。导出包含完整链的脱敏记录，筛选只限定选中对象，便于使用 `verify_entries(entries, anchor)` 离线核验链的连续性。导出文件应按实例内审计资料管理。`history(db, kind, id)` 返回资源各版快照、摘要及审计序号。

升级时一次性导入已有端点版本、可取得的平台当前版本、具名操作记录、运行事件、执行尝试和交付证据。旧记录保留原始时间和来源，无法推知的操作者标为历史未知，缺失的旧版本保持缺失。导入发生的时间另行记录，历史完整性不会被追认。

回归入口为 `PYTHONPATH=src python3.11 -m unittest discover -s tests -p test_audit.py -v`，涵盖事务回滚、并发、修改与删除检测、脱敏、导出、端点与运行证据，以及旧数据升级。
