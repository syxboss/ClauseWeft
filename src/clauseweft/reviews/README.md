# reviews · 独立评审与决议

对应 **F04 / A05、A07**，为 F06 的代码审查放行条件提供依据。意见、来源和签核决定由调用方的 SQLite 写事务统一提交。

## 评审对象和证据

需求评审绑定需求版本，代码评审绑定候选提交和需求基线。每条意见保留原作者/模型身份、位置、具体反例、严重度、建议与证据。相似意见可以分组，原件、反对意见及其来源不合并删除。负责人记录处置理由，阻断项还要有复核证据。reviews 拥有意见、答复、评审决议和其适用范围。

| Python 操作 | 输入与结果 | 主要失败 |
|---|---|---|
| 提交独立评审 | 评审分支、目标摘要和冻结的输入、若干意见 → 已提交的原始意见集 | 目标版本不匹配、意见无位置或证据、重复提交内容不同 |
| 裁决意见 | 意见 ID、处理方式、相关意见/修订、理由、负责人身份 → 可追溯决定 | 无权限；阻断项缺少复核记录不能算已解决 |
| 汇总指定版本的评审状态 | 目标版本或提交、必需评审集合 → 未完成分支、未关闭阻断项和可审批状态 | 旧稿意见不能直接批准新稿；被取消分支的迟到反馈只留历史 |

`submit(conn, run_id, target, branch, author, model_identity, findings)` 冻结已登记分支的意见。`resolve(conn, run_id, finding_id, actor, action, reason, evidence, related_ids)` 记录负责人的处置；阻断项须提供复核证据。合并重复意见后，原件仍可查询，关联处置尚未完成时继续阻止批准。`status` 返回缺失分支和仍开放的阻断项。代码评审目标绑定需求版本、候选提交及整合世代。

**验收例**：两位模型对普通成员是否能导出给出相反意见，负责人引用验收条件处理分歧。系统保留两条原文、决定及复核结果；代码提交变化后，界面仍能查看旧评审，但不能用它放行新提交。

工作台的意见列表会标出当前评审、已签核目标和历史版本。有审批权限的用户可以处置当前目标上的未决意见。阻断意见需要填写复核证据，其他意见可只填写处置决定和理由。选择合并重复意见时，可按位置、评审分支和反例勾选同一目标上的原始意见。
