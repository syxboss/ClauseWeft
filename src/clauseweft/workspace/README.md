# workspace · Git 工作区与补丁整合

`Workspace(root, repo, allowlist)` 打开已登记的仓库。在仓库外的私有目录保存基准对象、工作包补丁和候选提交。源仓库的索引、工作树和分支均保持原状。每个工作包使用独立的临时 Git 索引。Git 操作不检出或执行仓库文件。

| 调用 | 结果 |
|---|---|
| `snapshot(base)` | 返回解析后的提交 SHA 和准许传给模型的 UTF-8 文件路径、文本及 SHA-256。过滤符号链接、子模块、常见凭据文件和可识别的密钥。 |
| `stage_patch(base, patch, paths)` | 在基准索引上应用文本补丁，同时按仓库许可和工作包路径核对所有变更。允许普通文件的增删改，拒绝链接、路径越界和超过 1 MiB 的补丁。保存规范化后的差异并返回其 ID。 |
| `integrate(base, patch_ids)` | 按传入顺序应用同一基准的补丁并检测冲突。冲突返回相关补丁与路径。整合成功后在干净索引上重放差异、检查树散列并生成候选。 |
| `files(candidate_sha)` | 从固定 Git 对象读取受允许的普通文件，供受限执行器使用。最多 512 个文件，总计 2 MiB。 |

路径列表中的目录按路径段匹配，`.` 表示整个仓库。请配置实际需处理的子目录，文件名和内容筛查只覆盖已识别的凭据形式。补丁 ID、候选 SHA、树散列及可独立重放的 Git 差异都可由应用服务保存。修改选择后可以用相同的基准重新整合。

在仓库根运行 `PYTHONPATH=src python3.11 -m unittest discover -s tests -p test_delivery.py -v` 可验证并行分支的同行冲突、源仓库只读和在另一个干净克隆上重放。[接口与验收设计](../../../docs/05-详细设计.md)
