## 技能及上下文

技能由操作者维护为具名文本资源，字段为 `name`、`description`、`instructions`、`data_scope` 和 `enabled`。修改技能产生新的修订，历史正文及相应动作保留。角色通过 `skill_ids` 引用技能，单任务也可以显式指定，每次最多引用 16 个不同技能，指令总量最多 64000 字符。技能正文以文本方式进入模型消息，实际执行继续走平台登记的网关、工作区和验收适配器。

发布 SOP 时，服务端冻结所引用角色及其技能的实际内容和版本。普通任务在启动时冻结选定的角色与技能，复杂任务的规划、分支及汇总节点共用本次选择的技能。之后修改角色或技能不会改写已经保存的输入，当前启用状态与数据去向仍在派发前复查。引用的任一技能当前要求 `local_only` 时，服务端对整个运行采用仅本地策略。每个节点还要遵守自身冻结技能的数据范围，后续把技能改为 public 也不会放宽该节点原有的本地边界。固定云端和回退同样接受这些检查。

一次派发上下文由节点指令、技能、任务正文、当前返工意见和直接上游工件组成。请求证据在外发前保存，并按内容摘要关联到尝试。记录应能回答以下问题。

- 哪个运行、节点和世代准备了这次请求。
- 使用哪个发布模板、角色和技能修订，正文来自何处。
- 引用了哪些上游工件，实际发出的消息是什么。
- 选中了哪个端点和配置版本，输出上限和预算如何约束。
- 外部结果是否明确，返回的产物和用量关联哪次尝试。

原始模型消息保存在私有 `objects` 内容工件中，保留与实际派发一致的证据。上下文读取和导出提供脱敏展示，`context_sha256` 指向原始工件，`view_sha256` 对应返回的展示内容。脱敏后内容发生变化时，两种摘要用途需要分别核对。历史缺少请求证据时返回明确的缺失信息，便于审阅者判断可复验范围。模型供应商返回的答复和用量属于可观测证据，模型内部未返回的状态无法由平台重建。

## 检查点与派生运行

运行可以在没有活动派发或待核对尝试，也没有排队或执行中的整合、测试任务时创建具名检查点，固定运行计划、输入和节点结果。创建动作受当前运行版本控制，记录操作者、时间和说明。原运行之后发生变化，已保存检查点继续引用创建时的内容。

派生操作从检查点创建新的运行并分配独立预算。可以复用的模型结果保留原运行、节点、世代与产物来源。人工关卡及依赖其授权的下游重新处理，当前授权、端点、模型身份和数据范围重新复核。新调用遵守新运行的预算，原调用的费用继续留在原账本。

外部结果未知的尝试需要按账务与恢复契约处理。仓库交付的基线、候选、报告和签署决定通过既有需求修订及返工流程推进，检查点派生支持范围限定为文本单任务和通用 SOP，避免将旧候选的通过证据带入另一交付身份。

## 审计内容范围

所有可审计内容由业务实体、运行证据和访问事实共同覆盖，记录通过对象 ID、修订、运行 ID、尝试 ID 或内容摘要关联。

| 内容 | 保存的审计事实与证据 |
|---|---|
| 项目、需求、角色、技能与模板 | 资源正文修订、操作者、修改动作、历史内容及当前版本 |
| SOP 发布 | 发布者、模板修订、冻结节点、角色和技能版本 |
| 软件与部署配置 | 软件版本、路由规则、测试适配器、启动时磁盘上的源码、文档、测试与构建配置快照和文件摘要、脱敏部署配置及前后变化，清单不可取得时标明可用性 |
| 账号与会话 | 登录、注销、停用、角色变更、密码轮换等动作和结果，身份可关联 |
| API 访问 | 读写路径、操作者或匿名来源、脱敏请求正文及其摘要、结果和请求关联，覆盖成功、拒绝与失败 |
| 模型派发 | 运行、节点、世代、请求工件、路由决定、端点、配置版本价目和外部回执 |
| 模型及测试产物 | 内容摘要、归属、输出、真实测试报告及读取记录 |
| 人工决定 | 所批版本或节点、操作者、理由、结果及对应运行事件 |
| 费用与恢复 | 派发价目快照、有效 token 或明确缺失状态、预留、结算、待核对、对账依据、取消、暂停、恢复和失效事件 |
| 检查点及派生 | 固定来源、创建者、说明、复用结果、新运行及其独立预算 |
| 审计查询及导出 | 读取者、筛选条件、访问结果、导出边界和链校验信息 |

业务修改及其成功审计在对应事务提交。失败会回滚该次业务修改，再记录失败的请求事实。幂等重试可以保留再次访问事实，业务变更仍只生效一次。后台 worker 使用系统身份写入执行事实，运行创建者和人工签署者继续通过关联字段追溯。

软件清单固定每次启动时能读取的包源码、工作台 HTML、JavaScript、CSS 和仓库文档。`manifest_available` 表示已取得文件清单。可按 `clauseweft/` 下的 `.py` 条目核对收录的 Python 源码。字节码 zipapp 的部署清单仅含工作台静态文件及其摘要。文件运行期间再次变化会在下一次启动采集。该证据支持核对源文件与文档版本，持续文件监测和内存代码远程证明需要独立实现与部署验收。

认证密码、原始 Bearer 令牌和供应商凭据属于保管边界，审计保留动作和安全引用。业务正文与日志的常见敏感字串通过现有脱敏规则处理展示和导出，规则命中范围需要结合实际数据核对。私有源代码、需求和模型答复本身具有内容访问权限，运行证据沿所属项目授权检查，实例完整审计仅管理员可读。[工作空间与权限](10-工作空间与权限.md)

## 校验和导出

审计查询、链校验和完整导出仅供管理员。项目成员通过获授权运行的上下文、产物和交付报告核对自己的执行证据，不能读取全实例审计链。

审计记录按提交顺序追加，后继记录保存前一记录摘要，并对规范化内容计算当前摘要。校验检查链顺序、前驱关系及记录内容。修改、移除或插入记录会改变相应校验结果。

导出可以按项目或运行定位关注内容，同时保留完整实例链及命中条目的关联信息，筛选不改变跨空间证据的管理员访问边界，审阅者可以在独立环境重算摘要并核对链头。导出还包含已引用请求、产物、检查点及源码文档工件的脱敏视图、原始摘要和视图摘要，以及后台整合测试作业、评审、签署和评估记录，缺失或损坏的工件标为不完整。导出边界固定到一次已提交的记录位置，后续合法追加不会使该份历史导出失效。

读取审计、校验及导出操作自身有访问记录。一次查询返回的记录与链头对应读取时的边界，该次访问的完成记录会追加到后续链中，因此后续读到更高的位置是正常追加。审阅者核对一份导出时使用该文件自己的固定链头。

导出中的 `manifest_seq` 指向链内 `audit.export_prepared`。其摘要绑定证据视图、交付作业及业务记录三个分区，并固定导出时的数据库核验结果。浏览器直接下载原始响应，以保留 JSON 数字表示。可在独立环境运行 `PYTHONPATH=src python3.11 -m clauseweft audit --input audit-export.json`，核验链与附带内容。退出码 0 表示通过、1 表示内容不一致或证据缺失、2 表示文件或格式错误。

哈希链验证依赖受信的记录边界。具备数据库写权限的主体能够重写整条链，因此数据库管理者、服务进程和状态目录属于受信环境。将已导出的链头与导出文件在实例外保管，审阅者可以用前次基准核对后续记录及回滚情况。密码学签章、独立外部时间证明和只写存储属于后续企业部署能力。

旧平台审计和运行事件通过迁移保留原始身份、时间与内容，并明确标注历史来源。迁移时建立的链只能证明纳入之后的内容关系，旧版没有保存的请求或修改前正文按缺失处理。审阅者应同时查看迁移说明、软件版本和[验证记录](06-构建与运行.md)。

## API 与复验

所有接口位于 `/api/v1/`，沿用 Bearer 身份、写操作幂等键和修改前置版本。

| 入口 | 用途 |
|---|---|
| `GET/POST skills`、`GET/PATCH skills/{id}` | 技能维护与选择 |
| `GET {kind}/{id}/history` | 查询项目、需求、角色、技能、模板等资源保存过的内容修订和来源 |
| `GET runs/{id}/context` | 查询实际派发上下文及证据引用 |
| `GET/POST runs/{id}/checkpoints` | 查询检查点，创建时提交 `label,reason` 并检查运行版本 |
| `POST runs/{id}/forks` | 提交 `checkpoint_id,title,reason,budget`，根据检查点派生独立运行 |
| `GET audit` | 查询审计事实 |
| `GET audit/verify` | 校验当前审计链 |
| `GET audit/exports` | 导出完整验证链、筛选命中内容和脱敏证据，兼容 `audit/export` |

H01–H08 定义技能、输入、派生、访问、后台执行、校验和迁移的验收动作。回归使用临时 SQLite、Git 仓库和本地模型替身，真实容器执行另用固定本机镜像。测试命令、实际通过数及浏览器验证范围以[构建与运行](06-构建与运行.md)为准。新增扩展必须保留这些来源关系，并为失败、重试和并发提交定义同样可核对的结果。
