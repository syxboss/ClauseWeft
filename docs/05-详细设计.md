# ClauseWeft · 企业平台详细设计

产品版本 0.0.1 · 设计基线 v0.5 · 2026-11-21 更新。默认任务、按需多模型协作、Harness 和可信交付通过同一 HTTP API、SQLite 事务、内容工件及审计关联连接。界面收拢流程配置，执行中的授权、版本与证据约束继续由服务端检查。[产品需求](01-产品需求.md) · [概要设计](04-概要设计.md) · [Agent 设计](08-Agent设计.md) · [完整审计契约](09-Harness能力与审计.md)

## 1. 身份、会话与权限

HTTP 服务从 Bearer 凭据解析操作身份。启动管理令牌映射到 bootstrap 管理员，用于首次配置和兼容既有工作区。管理员可以创建密码账号，成员登录返回有效期 12 小时的会话令牌。服务端保存会话令牌散列，密码经独立随机盐和 scrypt 处理。会话校验读取当前成员启用状态、角色及显式数据授权，登出删除对应会话，重设密码或停用成员撤销其会话。

| 实例角色 | 可用操作 |
|---|---|
| admin | 全实例查询和业务写入，管理成员、授权、模型、可信配置、评估与完整审计 |
| operator | 在获授权空间及项目内查询、维护业务对象、配置角色和 SOP、执行任务、处理审批与查看成本 |
| viewer | 读取获授权项目、需求、运行及执行证据，拒绝写入和实例管理 |

成员的 `workspace_ids` 和 `project_ids` 是显式允许列表，非管理员访问项目须同时取得所属空间与项目的授权，空列表不表示全部。角色决定动作，数据授权决定对象。角色、技能和模板按空间共享；项目的需求、运行和全部嵌套证据继承项目权限。授权在读取、写入和幂等命中前复核，长准备过程之后在提交事务中再次核验。完整审计因包含全实例证明链只允许管理员访问。[工作空间与权限](10-工作空间与权限.md)

平台继续校验 Host、Origin 和 JSON 请求，当前默认监听本机回环地址。远程团队部署需要部署层的 HTTPS、访问控制和运维配置。[安全说明](../SECURITY.md)

## 2. 平台数据

`api/platform.py` 管理平台资源，`api/accounts.py` 管理成员与会话，`api/platform_setup.py` 建表和迁移历史记录，`storage` 提供事务。资源正文为规范 JSON，资源 ID、修订号和时间单独存储。时间采用 UTC 时间戳，API 中金额使用币种和整数微单位。

| 持久表 | 内容与约束 |
|---|---|
| platform_resources | kind 与 id 组成主键，保存工作空间、项目、角色、技能、模板和需求正文及 revision，空间归属保存在业务正文 |
| platform_releases | template_id 与 revision 组成主键，保存发布时冻结的节点、角色提示、技能正文与修订和模型绑定 |
| platform_members | 唯一 username，成员显示名、实例角色、工作空间和项目允许列表、密码散列、盐、启用状态和 revision |
| platform_sessions | token_hash 为主键，关联成员及到期时间 |
| platform_run_links | run_id 唯一关联项目、需求、标题、模板发布版本和创建身份 |
| audit_entries / audit_head | 统一追加审计记录及其链头，保存身份、动作、结果、关联与前后摘要 |
| audit_resource_revisions | 保存可审计资源的修订正文、内容摘要、来源和对应审计位置 |
| audit_migrations | 标记旧平台审计、运行事件和可恢复资源的迁移来源 |
| harness_checkpoints | 保存检查点身份、来源运行、创建者、说明及内容工件摘要 |
| deployment_snapshot | 保存最近一次软件、配置、可取得的源码与文档清单及正文工件引用，启动审计保留前后变化 |
| api_requests | 动作、幂等键、请求摘要和已提交响应 |
| attempts 的 pricing_snapshot / usage | 派发时固定模型和版本价目，结束时记录合法回执 token 或明确缺失/非法状态 |

首次安装持久记录初始化完成状态，建立空的默认团队空间与只有一个项目和一条待配置模型单任务的示例空间。初始化时跳过需求、SOP 和审批。重启不重复生成示例。升级时，已有项目归入默认团队空间，缺少项目链接的旧运行按需归入历史默认项目，已有运行 ID、需求版本、候选 SHA 与工件引用保留。从未保存显式授权的旧版升级时，非管理员保持无数据授权，由管理员分配允许列表；已有允许列表在后续升级中保留。新增平台实体通过资源 ID 与运行关联，业务需求与执行需求版本分别建模。

工作空间保存名称、说明、示例用途标记及允许的 repository_ids、endpoint_ids。项目字段为 name、description、workspace_id、repository_id、status、color。绑定仓库时必须引用受信配置登记的 repository_id。需求字段为 title、description、project_id、status、priority、assignee，其空间从所属项目取得，创建后项目归属固定。需求状态包括 backlog、ready、in_progress、review、done，优先级包括 low、medium、high。

角色字段为 name、description、workspace_id、stage、prompt、endpoint_id 和 skill_ids。阶段取 requirements、review、code、test，端点为空时由路由选择。技能保存 workspace_id、独立文本正文、状态和数据范围，正文随修订保管。模板字段为 name、description、workspace_id、execution_mode、nodes。角色、技能、模板引用与执行项目必须属于同一空间。模板草稿和发布快照分开保存，运行固定发布版本、角色和技能内容。

## 3. 任务、角色与执行图

普通入口接受项目、任务内容和可选模型选择，`mode` 默认为 single，普通单任务阶段默认为 general。创建运行时无需先创建 requirement_id、role_id 或 template_id。用户明确选择模型时仍校验工作空间模型授权、数据范围、上下文、价格和当前启用状态。高级自动阶段继续保留意图判断与解释，专业阶段保留对应路由规则。

普通任务可选顶层 `role_id`。服务端从运行的工作空间读取角色，在启动时固定提示、阶段、技能和端点绑定。角色阶段优先，显式模型与角色绑定冲突时拒绝提交。用户原文放入 `task.text`。审计与实际上下文可以追溯本次使用的角色修订和指令。

`mode=complex` 要求显式的 `budget.currency` 和 `budget.limit_micros`。预览只计算首个规划节点。有效规划回执触发建图，生成 2 至 8 个分支及依赖所有分支的汇总节点。规划模型提交分工文本，依赖、节点 ID 和可执行动作由服务端生成。调用方可用 `max_concurrency` 控制运行并发，用 `task.pinned_endpoint` 固定整个任务的模型。每次派发从同一运行预算预留，取消、迟到回执和并发争用按尝试处理。[请求与读取示例](11-任务执行与模型用量.md)

### SOP 编译与版本

节点至少包含 node_id、kind、stage 和 dependencies，可再携带 label、role_id、prompt、pinned_endpoint 和独立模型分组。当前通用 SOP 提供 model 与 gate 两种节点。编译检查唯一 ID、节点类型、阶段、依赖存在、无环及模型节点配置。

创建研发交付模板时，若没有已有模板可以复用，服务端按内置研发流程生成第一份草稿。自定义 SOP 须提供节点，显式提交的空节点列表会被拒绝。保存模板产生新的资源 revision。发布时读取模板草稿及引用角色，将角色提示、角色版本、端点绑定和技能正文复制到节点，校验后写入不可变发布记录。再次发布同一内容复用该发布版本。角色或技能已修改而模板 revision 未变化时，要求先保存模板的新版本再发布，避免同一发布编号出现不同输入。

创建运行时由服务端读取已发布快照，固定 template_snapshot 和节点定义。客户端提交项目、需求、模板 ID 及任务意图，不能把任意客户端价目或未经校验的快照直接当作执行授权。之后修改模板或角色只影响后续发布和运行。

仓库研发模式可通过 mode=workflow 直接使用内置 delivery-v1，无需 template_id 或先创建和发布自定义 SOP；工作台接收已登记仓库、基准提交、验收套件和总预算。该模式沿用专门关卡与领域检查。其必需节点、类型、阶段、依赖和独立模型分组保持固定，模板可以配置显示名称、角色提示及模型绑定。它保存需求基线、两个独立评审、实现与测试设计、整合候选、代码评审、必测执行和最终接纳。通用 SOP 的人工批准只推进对应依赖，仓库交付的批准还要通过版本、评审和测试门槛。

## 4. 路由、派发与预算

路由从完整任务消息、当前节点阶段和候选端点生成冻结快照。硬约束包括当前授权、启用状态、数据去向、上下文窗口、能力、币种、价格和可用预算。固定端点也通过同样检查。合格候选先按适配等级，再按成本、质量或延迟偏好排序，观测不足时回退到人工优先级，同分按端点 ID 稳定决定。

预览为本机纯计算。派发前重新检查当前目录、网关绑定、输入引用、模型身份、租约和预算。独立模型分组按已核实的底层身份分配，保留已完成或已派发成员的身份占用。同一模型的两个别名无法填满两个独立席位。

`claim` 在事务中领取就绪节点并创建尝试。`dispatch` 在后续短写事务写入本次尝试的决策、预算预留与派发意向，提交后才调用网关。worker 的网络和文件读取放在短写事务之外，提交回执时重新检查世代和当前尝试。

派发证据还保存该次完整消息、节点定义、输入引用、技能快照、端点及限制，并以内容摘要关联尝试。请求证据与实际外发内容在同一派发过程中固定。查询接口返回脱敏展示以及原始证据摘要和展示摘要，历史请求缺失的旧尝试明确标为 legacy_missing。引用的任一技能当前要求本地处理时，整个运行收紧为 local_only，每个节点还保留其冻结技能的数据边界。固定模型及回退通过同样检查。

普通单任务未提供 budget 时，服务端用当前已配置且获授权模型的币种和价目计算有限的单次执行上限，来源为 model_estimate。自动候选存在多种合格币种时，要求用户选择一个模型或显式指定币种和预算；不自动换汇。显式预算的来源为 explicit，没有模型时标记 no_configured_model，并不会建立可调用的默认模型。预览返回预算及来源。复杂任务省略预算会被拒绝。旧的仓库交付和 SOP API 在省略预算时使用 USD 零额度，来源为 explicit_required_for_paid_workflow，符合币种与其余约束的零价模型仍可派发。

可用金额等于运行预算上限减去已结算金额和全部未结预留。每笔调用按输入价格、保守输入量、输出上限与输出价格估算并向上取整，未知价格不能穿过硬预算。两个并发分支各需预留 0.70、余额 1.00 时，最多一笔成功。当前分支分别原子预留，整组一次预留作为后续计划能力。

派发时将 endpoint_id、endpoint_revision、model_identity、currency 及输入/输出单价写入不可变 pricing_snapshot。结束时将回执归一化到 usage，status 为 reported、missing 或 invalid，只有合法的 prompt_tokens、completion_tokens、total_tokens 且合计一致时保留数字。有效用量按派发价格结算并释放差额，整数微单位金额向上取整。

结果未知、超时和已派发取消保留可核对预留。费用对账记录操作人、依据和实际金额，迟到回执可以更新历史账务，同时受当前节点发布权约束。对账不重写原 token 回执，更新模型价目不重算旧调用。界面分别列出已结算、预留和待核对项。

### 按模型统计

`usage.Usage.report` 先取得当前空间内获授权的项目，再读取其实际尝试，按 endpoint_id、endpoint_revision、currency 分组。models 提供调用次数、实际输入/输出/合计 token、失败次数、已结算及预留金额、待核对调用、模型身份和 pricing_snapshot。totals 只按币种分组，未选择换汇口径时不生成跨币种总金额。

任一调用缺少合法用量时，该组 input_tokens、output_tokens、total_tokens 返回 null，usage_complete 为 false；known_input_tokens、known_output_tokens、known_total_tokens 仅表达已记录的小计，missing_usage_calls 表达缺失数量。没有调用的当前配置模型显示 calls=0，不产生虚构订阅或调用费。已经撤出当前空间的模型，其历史数据仅在调用所属项目仍获授权时纳入。

旧尝试没有 pricing_snapshot 时，可从其明确的 endpoint_revision 恢复价目，来源标为 historical_catalog 或 historical_snapshot，不能使用最新价格。找不到历史价目时标为 unavailable。旧用量未记录时保持缺失，不从文本长度或金额猜测 token。平台计价依据与供应商最终账单的边界见[模型用量](11-任务执行与模型用量.md)。

## 5. 状态、取消与恢复

| 节点状态 | 进入与后续处理 |
|---|---|
| waiting | 等待依赖，当前上游全部成功后才可就绪 |
| ready | 可领取，实际派发仍需重新核验策略与余额 |
| leased | worker 已领取，尚未登记外部派发意向 |
| dispatched | 派发意向与预留已提交，可进行外部调用 |
| succeeded | 产物在当前世代发布成功 |
| needs_input | 人工关卡、配置、业务门槛或明确错误需要处理 |
| uncertain | 外部结果不明，保留历史与费用待核对 |
| cancelled | 运行取消后封闭新增派发和产物发布 |

租约到期且尚未派发的节点可重新领取。已有派发意向的尝试需要核对外部结果，恢复不会静默重放。有效成功节点继续复用，输入变更导致下游失效并递增世代。旧回执保留为历史，同一尝试和同一网关回执不能重复结算或发布。

人工操作检查最新运行 revision 和业务前置。取消封住新增派发及当前发布权，已产生外部费用继续保留。取消终态需要显式新建运行。通用 SOP 和仓库流程共享运行账本与事件模型，具体可恢复动作以 waiting_actions 呈现。暂停阻止新的节点领取，恢复后继续派发。通用人工关卡 action 为 approve 时记录依据并推进，reject 时将该关卡的直接前序节点与相关下游作废，附返工意见重跑。

检查点保存时拒绝 leased、dispatched、uncertain 节点，以及排队或运行中的整合、测试任务。检查点将运行正文、节点定义、状态、世代和产物写入内容工件，再保存创建者、说明和来源运行版本。单任务和通用 SOP 可以从检查点派生，仓库研发的派生入口返回明确拒绝。

派生运行沿用冻结模板与技能，并显式提供新预算。只有已成功的模型节点、且全部依赖均为已继承模型成果时，才可复用其产物，记录原运行、检查点、节点、世代、尝试与产物。人工关卡不被继承，其下游重新运行。新派发仍复核当前策略和端点，原费用保留在原运行。原运行后续变化通过独立世代及工件引用与派生运行区分。

## 6. 评审、候选与实测

需求修改产生不可变新版本，条款以稳定 ID 和验收条件保存。评审意见绑定目标版本或候选，保留作者、独立模型身份、定位、严重度、反例、建议和证据。合并重复意见通过引用保留来源。审批需要当前目标、全部必需评审和已关闭的阻断意见。

仓库基准固定为可解析 SHA。模型只读取服务端筛选的允许文件。补丁按工作包路径限制检查，在私有 Git 索引中应用与整合，冲突进入显式处理，候选记录来源补丁、基准 SHA、候选 SHA、树散列和可重放差异。

套件由负责人可信配置登记，固定必测 ID、条款映射、命令、输入、预期输出、镜像和时限。执行器在固定 Docker 镜像的一次性受限容器中运行登记 argv。候选进程获得本次输入，期望输出保管在宿主适配器。输出、退出状态、缺文件、超时与实际命令组成执行证据。

接纳事务重新读取当前基线、候选、代码评审、套件及环境，核对每项必测证据。报告必须指向同一候选与环境，缺项、跳过、失败和超时不能放行。交付清单固定需求、决议、候选、补丁、报告及条款映射，导出重试保持幂等。[测试执行器](../src/clauseweft/testing/README.md)

## 7. HTTP 资源

所有应用接口以 `/api/v1/` 开头，使用 UTF-8 JSON。读取列表支持 limit、cursor 和 next_cursor，运行事件使用 after 续读。平台资源支持 project_id 等筛选，成员接口以服务端角色决定可读写范围。

| 入口 | 主要用途 |
|---|---|
| POST auth/login，GET auth/me，POST auth/logout | 密码登录、当前身份及注销会话 |
| GET/POST workspaces，GET/PATCH workspaces/{id} | 查询获授权空间，管理员维护空间和允许的仓库、端点 |
| GET overview | 当前空间内获授权项目、运行、按需审批和按币种费用汇总，管理统计按角色返回 |
| GET usage | 按 workspace_id、可选 project_id 返回获授权项目的模型版本用量和分币种汇总，仅管理员与操作者 |
| GET/POST projects，GET/PATCH projects/{id} | 项目维护 |
| GET/POST requirements，GET/PATCH requirements/{id} | 需求目标、状态和优先级维护 |
| GET/POST roles，GET/PATCH roles/{id} | 角色职责、提示及端点绑定 |
| GET/POST skills，GET/PATCH skills/{id}，资源 history 入口 | 技能正文、数据范围、状态和资源历史修订 |
| GET/POST templates，GET/PATCH templates/{id}，POST templates/{id}/publish，GET templates/{id}/versions | SOP 草稿、发布与冻结版本信息 |
| GET/POST members，PATCH members/{id} | 管理员维护成员账号、角色、workspace_ids、project_ids、启用状态和密码 |
| GET audit，GET audit/verify，GET audit/exports，GET settings | 管理员查看审计记录、链校验、完整链导出与可信配置 |
| GET/POST endpoints，PATCH endpoints/{id}，POST endpoints/{id}/probes | 模型资源、启停和连接/能力探测 |
| POST routing/previews，POST runs，GET runs/{id} | 选模预览、启动执行、读取完整运行 |
| GET runs/{id}/attempts，GET runs/{id}/events，GET runs/{id}/artifacts/{id} | 派发、费用、事件和工件 |
| GET runs/{id}/context，GET/POST runs/{id}/checkpoints，POST runs/{id}/forks | 实际请求证据、检查点及有来源的派生运行 |
| POST runs/{id}/specs，POST runs/{id}/findings/{id}/resolutions，POST runs/{id}/approvals | 需求版本、意见处置和业务审批 |
| POST runs/{id}/integrations，POST runs/{id}/tests，POST runs/{id}/rework | 候选整合、实测及工作包返工 |
| POST runs/{id}/gates/{node_id} | 通用 SOP 人工批准或退回，正文包含 action 和 reason |
| POST runs/{id}/pause，POST runs/{id}/cancel，POST runs/{id}/resume，POST runs/{id}/reconciliations，POST runs/{id}/exports | 暂停、取消、恢复、对账与交付导出 |
| POST evaluations，GET evaluations/{id}，GET evaluations/{id}/blind，POST evaluations/{id}/grades | 规则回放、配对实测与盲评 |

所有业务写操作携带 Idempotency-Key，修改已有资源再携带 If-Match。服务端先鉴权，随后在同一事务读取同键请求缓存、检查 revision 和业务条件、提交状态与审计，再保存幂等响应。不同身份的幂等记录必须隔离。同键异参返回 409，过期版本返回 412，缺少版本返回 428，非法输入返回 422，越权返回 403。成功业务与成功审计原子提交，失败修改回滚后另记访问失败，幂等命中不会重复业务内容修订。

下面为普通任务请求。替换为自己的空间、项目与已登记模型 ID。省略 mode、需求和模板；选定模型后可省略手填预算，由服务端按当前价目生成有限上限。

```json
{
  "workspace_id": "workspace-id",
  "project_id": "project-id",
  "title": "检查导出方案的边界",
  "task": {
    "text": "核对管理员、普通成员和空结果时的预期行为，并列出可验证条件。",
    "pinned_endpoint": "configured-model"
  }

```

需要修改代码并验证时，直接选择 mode=workflow 并提供 repo_id、base_sha、suite_id 及 budget；使用内置流程不要求 template_id。复用自定义协作时再提供已发布的 template_id。客户端不能提交服务端保管的继承来源、角色修订、技能快照或执行证据，模板节点使用允许字段清单。高级执行继续遵守对应版本与实测契约。

## 8. 审计存储与完整性

`audit` 接收平台、HTTP 与执行器产生的事实，统一关联身份、动作、对象、结果、项目、运行及请求。资源修订保存脱敏正文和内容摘要，审计记录保留修改前后的内容摘要与来源，后台运行事件保留事件位置与尝试关联。API 访问保存脱敏请求正文及其摘要，认证密码与原始令牌从审计载荷剔除。

启动审计保存当时磁盘上可取得的代码、文档、测试、构建配置及部署配置的快照与清单摘要。它记录每次启动观察到的文件内容和前后变化，运行期间的文件改动须在下次启动重新纳入。内存中实际执行代码的远程证明与持续文件监测属于独立能力。原始模型请求工件保存在私有对象目录，接口及导出返回脱敏视图，并分别标明原始内容摘要与视图摘要。

每条记录包含前驱摘要及自身规范化内容摘要，链头保存实例账本 ID、已提交位置和摘要。验证检查顺序、前驱、条目内容及资源修订引用，导出同时给出完整链和筛选命中的条目 ID。审阅者可以按固定导出边界复算摘要。数据库管理者能重写数据库与链头，独立保管的导出基准用于增强核对，完整边界见[Harness 能力与审计](09-Harness能力与审计.md)。

## 9. 评估口径

规则回放只报告决定与约束违规。配对实测冻结题集、允许端点、模型版本、价格和单题预算，再为固定与自动策略分别启动运行。缺少输入或预算的题仍留在分母，其他合法题继续执行。

每侧报告总题数、已执行、通过、失败、产物待评分、执行待定和未执行数量。已明确拒绝的调用计入失败，费用尚未核对时另列待核项。单位成功成本包含该侧全部失败与重试，仍有未知费用时保持未定。耗时取有终止证据的样本并显示样本数。双侧都有最终判断的同题才进入胜负对照。[评估模块](../src/clauseweft/evaluation/README.md)
