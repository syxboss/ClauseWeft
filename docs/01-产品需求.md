# ClauseWeft · 目标驱动研发产品需求

产品版本 0.0.1 · 2026-11-25 更新。ClauseWeft 是本地优先的可控 AI Agent 编排与软件工程工作台：支持个人本机配对与团队权限边界，整合多模型确定性路由、多协议独立网关、受控 MCP 与项目工具、容器隔离外部编码 CLI、知识库与项目长期记忆，以及离线可核验的完整审计链。[验收基线](02-需求评审.md) · [Harness 能力与审计](09-Harness能力与审计.md) · [后续演进与路线图](13-后续演进与路线图.md)

## 产品定位

产品主线为 **本地优先、可控可验的 AI Agent 编排与软件工程工作台**：围绕项目与目标组织人机协作，将多模型推理、受控工具与外部编码 Agent 统一纳入服务端权限边界、预算预留、真实用量账本与离线审计证明之中。

默认路径保持极简：创建项目、提交目标、查看结果与证据。普通任务可直接选定模型或上传文本/图片材料执行；复杂问题按需开启并行分工、MCP/项目工具（含只读自动审批与写入人工确认）、容器隔离外部编码 CLI（支持固定镜像测试、行级评审评论与有界自动修复），或复用已发布的团队 SOP（组合 `model`、`agent`、`gate` 节点）。

通用企业办公与行政流程管理不属于本产品范畴；所有功能均围绕可复现、可核对的研发与知识工程执行契约独立设计。

当前交付以自托管单实例建立平台基础。实例角色决定操作权，显式工作空间和项目授权决定数据范围。组织目录接入、每项目独立角色、跨实例调度及容量扩展按后续验收推进。

## 用户与工作空间

| 角色 | 主要工作 | 权限要求 |
|---|---|---|
| 平台管理员 | 维护成员、模型资源、可信执行环境与平台设置 | 可配置成员及角色，敏感凭据通过受控引用提供 |
| 研发操作者 | 在授权项目提交目标、执行任务、读取结果，按需要启用协作和代码交付 | 所有读写由服务端检查工作空间及项目授权，保留身份和对象关联 |
| 审阅者 | 在任务需要复核或交付判断时查看内容、差异与测试证据并处理关卡 | 审批绑定当前产物版本，理由随决定持久化 |
| 只读成员 | 查询获授权项目进展与历史执行证据 | 读取页面与 API，业务写入和实例管理接口由服务端拒绝 |

本次以 admin、operator、viewer 三个实例角色实现。审阅能力归入可写操作者，后续可拆出独立审批角色。非管理员必须同时取得工作空间和项目的显式授权，新账号默认无业务数据访问权。角色、技能和模板属于指定工作空间，项目承载需求、运行及其证据；总览、审批和费用只汇总当前空间内获授权的项目。模型端点、账号、可信配置、评估和完整审计由管理员管理，普通成员不显示对应管理菜单，直接 API 同样拒绝。[角色与授权矩阵](10-工作空间与权限.md)

首次个人配对建立持久所有者及默认个人项目。已有团队实例继续按原有项目和授权访问。独立的“示例工作空间”仅包含一个项目和一条待配置模型的单任务，不创建需求、SOP 或审批，重启不重复生成。示例标识与业务空间隔开，不伪造模型调用或容器通过结果。升级保留原有数据、候选和审计，将旧业务归入默认团队空间，从未保存显式授权的旧版升级时，非管理员须补充分配范围；已保存的授权继续保留。

## 平台信息架构

| 默认入口 | 用户需要完成的事 | 必须可见的信息 |
|---|---|---|
| 工作台 | 提交目标并找到需要继续处理的任务 | 当前工作空间和项目、任务状态、最近结果、模型配置缺口 |
| 项目 | 整理目标和任务，切换授权范围 | 名称、说明、任务与关联结果 |
| 任务 | 提交执行、读取产物与处理异常 | 原始内容、所用模型、执行状态、结果或失败原因 |
| 模型用量 | 核对实际模型消耗 | 模型和配置版本、输入/输出 token、调用次数、币种、已结算和待核对 |
| 模型配置 | 管理员接入模型并设置真实价目 | 网关别名、模型身份、连接状态、数据去向、币种及输入/输出单价 |
| 团队与审计 | 管理员授权和核查执行 | 成员权限、工作空间资源授权、身份、内容版本和审计依据 |

需求、角色、技能、SOP 和审批收纳在“协作”分组内。选择这些能力不会改变工作空间及项目权限。任务详情默认先展示内容和结果，普通单任务无需理解节点图；多步骤任务继续显示必要的步骤、依赖、产物及等待原因。请求上下文、检查点、详细账务与原始证据按需读取。

界面使用持久导航、工作空间及项目上下文、内容区和详情面板。列表须支持空、加载、失败和筛选无结果状态，长任务自动更新。模型未配置时展示配置入口，不填充演示模型、价格、调用次数或成本。

## 默认执行与按需协作

1. 个人配对后可直接使用默认项目。文本任务需先连接模型；外部仓库任务按[个人工作台与外部 Agent](12-个人工作台与外部Agent.md)登记执行器和文件范围。
2. 操作者填写任务目标和内容，选择获授权模型后提交。普通单任务无需创建需求、角色、模板或审批。
3. 平台检查内容范围、端点及预算，保存实际请求，执行后先展示结果与状态。模型用量按真实调用持续更新。
4. 目标可拆为多个独立问题时，操作者选择复杂任务并指定总预算。模型先列分工，服务端调度各分支并在全部成功后汇总。要按团队既定步骤复核或等待人工决定时，选择已发布的计划。
5. 修改代码并验证时，直接选择内置代码交付，提供已登记仓库、基准提交、验收套件及预算，不要求先创建角色或发布 SOP。批准需求基线后派发受限实现和测试设计，整合唯一候选，经独立代码评审与固定镜像必测后接纳。该模式的审批和实测门槛继续由服务端执行。

自配模型和可解释路由为执行基础。普通任务支持 `general` 通用阶段，明确选择模型时不会因文本未匹配某个研发意图而要求先走需求澄清。高级自动选模继续按阶段、数据范围、上下文、能力和费用约束选择，意图不明时明确反馈。

## 自配模型与实际用量

模型不随安装自动开通。管理员在独立网关维护供应商连接和凭据引用，在平台登记模型能力、币种及每百万输入/输出 token 单价，并向业务工作空间分配允许端点。零价须由配置者明确填写；缺少价目不按免费处理。

每次调用的计价、币种和模型版本固定到尝试。合法用量回执按该版本计算金额，价格修改不重算历史。成本包含失败、重试和已发生的调用，未知结果、缺失或非法用量保留待核对状态；有记录的对账金额与 token 回执分别保存。金额按币种分列，平台不自动换汇。

普通选定模型的单任务未提供预算时，服务端依据该模型币种、价目和当前请求上限计算有限的单次执行预算。页面可在高级设置中提供更明确的限制，不使用固定美元预算或安装时的示例金额代替实际配置。平台统计是价目和可观测用量的计算，供应商最终账单另行核对。[执行与用量口径](11-任务执行与模型用量.md)

## 功能要求

S01–S03 定义默认任务路径。E、F 与 H 保留平台、模型执行和证据能力，其中需求、模板与审批在任务选择相应模式时启用，不构成普通任务的前置步骤。

| 编号 | 平台要求 | 验收要求 |
|---|---|---|
| S01 简单执行 | 常规任务直接填写目标、项目和已配置模型 | 不创建独立需求或模板也能执行并读取结果 |
| S02 按需协作 | 将自动路由、独立评审、角色技能与 SOP 作为任务需要时启用的能力 | 默认路径简洁，高级分支保留输入、状态和产物关系 |
| S03 自配与计价 | 管理员自行接入模型及真实价格，成本按实际尝试统计 | 无预置可用模型，币种不混算，历史价目及未知费用可核对 |
| E01 项目与需求 | 多项目和独立需求实体，需求可关联运行 | 创建和修改后刷新、重启仍可查询，项目筛选一致 |
| E02 SOP 生命周期 | 可视化编辑节点与依赖，保存草稿、校验和发布版本 | 循环依赖或悬空边拒绝发布，运行绑定已发布快照 |
| E03 角色复用 | 提示、任务阶段、技能和模型绑定组成角色，可供单任务或 SOP 引用 | 后续修改角色不会改变已启动运行的输入 |
| E04 账号与权限 | 账号登录、会话、admin/operator/viewer 服务端控制 | 只读成员直接请求写 API 仍被拒绝，登出会话失效 |
| E05 统一审批 | 人工关卡、需求基线和交付审批可集中处理 | 陈旧版本拒绝，批准后节点继续，记录处理人和理由 |
| E06 可观测性 | 总览、运行节点、日志、产物、用量和审计共享真实数据 | 指标由持久化记录计算，失败和未知不显示为成功 |
| F01 模型池 | 新增、编辑、启停和探测端点，保管密钥引用 | 能力验证与连通区分，目录版本和模型身份可核对 |
| F02 动态路由 | 内容与阶段、硬约束、偏好、手动固定和受限回退 | 相同快照重放相同决定，显示候选、淘汰原因及数据去向 |
| F03 并行编排 | 依赖就绪的节点可并发，独立评审按底层模型去重 | 必需分支齐全才汇合，部分失败保留成功分支 |
| F04 需求与评审 | 修订版本、处理分歧、批准基线 | 修改使下游旧审批和产物失效，历史仍可读 |
| F05 编码整合 | 隔离基准、受限补丁、显式冲突处理和候选版本 | 无静默覆盖，干净基准可重放相同代码树 |
| F06 测试交付 | 登记命令与必测项，固定环境真实执行并导出 | 缺文件、失败和超时均不能放行，证据绑定候选 |
| F07 运行控制 | 费用预留、重试、取消、恢复和对账 | 同一次写重试幂等，未知外部结果保留账目 |
| F08 路由评估 | 规则回放、固定与自动两侧运行、盲评和成本 | 缺题留分母，费用未知单列，统计包含失败重试 |
| H01 技能版本 | 维护文本技能，供角色与单任务显式选择 | 每次修改保留历史，停用后的新派发受当前策略检查 |
| H02 上下文来源 | 冻结技能、角色、任务和上游产物组成的输入 | 技能版本随发布快照固定，任一当前本地技能会收紧整个运行，节点继续遵守冻结数据边界 |
| H03 请求证据 | 为每次实际派发保存完整请求及内容摘要 | 可查询消息、节点、输入引用、端点和输出上限，历史请求不受返工覆盖 |
| H04 检查点与派生 | 单任务和通用 SOP 在稳定状态生成检查点并派生运行 | 新运行具有独立预算，人工关卡及其下游重新判断，原运行保留 |
| H05 内容与动作审计 | 记录资源版本、配置、读写、拒绝、失败和人工决定 | 操作者、对象、结果、依据和内容引用可关联，认证凭据不进入审计正文 |
| H06 执行审计 | 将派发、回执、费用、失效和恢复关联到审计 | 同一运行事件与尝试能定位请求、产物和账务证据 |
| H07 完整性与导出 | 校验记录链并导出可离线核对的证据 | 筛选结果保留完整链验证所需内容，篡改或缺失能被校验发现 |
| H08 升级与边界 | 旧记录纳入可追溯迁移，界面明确证据范围 | 旧记录标注历史来源，旧请求不补造，具数据库写权限的运维仍属受信边界 |

## 路由与执行的关键契约

任务先提取意图、阶段和上下文要求，再按端点启用、许可、数据范围、上下文窗口、能力、价格、币种及预算筛选。排序先用任务适配等级，再用成本、质量或延迟偏好。观测不足时使用人工优先级并展示原因，同分以端点 ID 决定。高级自动意图不明确时等待补充；普通 general 任务不因缺少专业阶段匹配而要求澄清。固定模型仍要通过相同的数据、能力和费用约束。

预览冻结输入并本机计算。实际派发和回退前重新检查当前授权、端点绑定、模型身份和可用预算。在持久化派发意向与预算预留后才请求独立网关。需要不同模型的并行组按核实的底层身份去重，同模型别名不能占据两个独立席位。

需求审批绑定需求版本，评审和测试绑定候选。取消、输入变更和迟到回执保留历史，同时检查当前世代是否允许发布。API 写重试使用同一幂等键，修改已有资源检查 If-Match，业务、版本、事件和幂等结果在同一事务提交。

模型可见的技能、角色、任务与上游内容必须有来源和版本，实际派发前固定请求证据。检查点保管旧运行的输入与已完成成果，派生时重新检查当前授权和端点，分配新预算，重新经过人工关卡。仓库研发通过原版本和候选流程返工，继续保留完整交付门槛。

所有业务接口的访问和结果、后台执行事件及配置变更都有对应审计事实。业务修改失败时不记录为修改成功，可以另行记录被拒绝或失败的访问。审计导出和敏感上下文读取本身也需留身份与结果。脱敏展示与原始请求内容摘要分别表达，以便核对来源和展示形式。[审计范围与校验](09-Harness能力与审计.md)

## 企业推广条件

平台以目标提交、模型协作、结果与证据形成闭环。普通单任务可使用一个合格模型；选择要求独立评审的代码交付模式时，才要求足够的独立模型及可信验收环境。生产推广分别核验备份恢复、容量、真实供应商质量和账单、目标业务仓库及部署环境。SSO、组织目录、每项目独立角色与逐动作自定义授权、不可信多租户隔离、高可用数据库和分布式 worker 为单独的扩展验收项。每项交付以测试与运行证据确认，具体结果维护在[构建与运行](06-构建与运行.md)。
