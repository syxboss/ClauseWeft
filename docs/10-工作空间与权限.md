# ClauseWeft · 工作空间、示例与权限

产品版本 0.0.1 · 内容核对日期 2026-11-21。本页定义首次安装的数据边界和成员访问规则。工作空间是实例内的业务边界，项目是需求、运行和证据的数据授权边界。平台角色控制允许执行的动作，两种数据授权同时约束可访问对象。[产品需求](01-产品需求.md) · [API](../src/clauseweft/api/README.md) · [安全边界](../SECURITY.md)

## 首次安装

一个状态目录由一个控制进程管理，目录里可以保存多个业务工作空间。配置文件中的 `workspace_id` 仍标识部署实例，业务工作空间使用各自的资源 ID，两者用途分别保留。

初始页默认选择「个人配对」。在空实例上输入启动令牌后，工作台创建一个具名本机所有者，在「我的工作空间」中准备「我的项目」。每次配对签发独立的 12 小时会话。浏览器只保存该会话；关闭浏览器后也可在到期前继续工作，主动退出会立即撤销当前会话。重新配对会恢复原有身份、任务和偏好。

选择「已有账号」可进入现有团队实例，选择「管理员」可执行恢复和配置操作。个人配对仅初始化未使用的实例；若数据库已有成员、业务项目、模型或修改后的示例，服务会返回 409。升级旧实例时仅允许原始示例记录与普通本机配置；遗留的非初始化审计、已登记仓库、远程网关或配置切换记录仍由原实例管理。原有数据库可继续作为团队工作台使用。在另一状态目录和端口启动个人工作台可独立保存数据。

初始数据含一个独立的「示例工作空间」，内有一个项目和一条待配置模型的任务。示例没有独立需求、SOP 或人工审批。初始化和配对均不触发模型调用或容器验收。顶部工作空间选择器可切换示例，项目筛选和统计仅覆盖当前空间内获授权的项目。

初始化状态持久保存。重启不会重复增加示例项目、运行、成员或历史记录，也不会把用户已修改的示例重置。升级保留已有项目、需求、运行 ID、候选、测试、审批和审计，原内容明确归入默认团队空间。从没有显式授权的旧版升级时，非管理员账号需要由管理员补充分配授权，迁移不会默认为其开放全部实例数据。已经保存的允许列表在后续升级中保留。0.4 及更早安装中已有的需求、SOP 和人工关卡示例按历史保留，不因简化默认路径而改写。无法确定用途的旧数据继续保留，不根据名称自动删除或当成系统示例。

## 角色与数据授权

| 身份 | 业务范围 | 菜单和操作 |
|---|---|---|
| 管理员 `admin` | 全实例，包括团队和示例工作空间 | 工作台、项目、任务，以及“协作”和“资源与管理”中的配置、用量、团队设置和完整审计 |
| 操作者 `operator` | 显式授权的工作空间及项目 | 工作台、项目、任务和授权范围的模型用量，在“协作”维护需求、角色、技能、SOP 和处理审批 |
| 只读成员 `viewer` | 显式授权的工作空间及项目 | 工作台、项目和任务结果及执行证据，不提供写入、审批、模型用量汇总和实例管理入口 |
| 未获授权成员 | 无业务数据 | 可登录并查看自己的身份，展示无授权状态，由管理员分配范围 |

普通任务可直接提交。“协作”和“资源与管理”按账号能力显示。具体可用页面和接口仍按当前角色与授权核验。

成员的 `role` 为实例角色，`workspace_ids` 和 `project_ids` 是显式允许列表。非管理员读取项目时，项目自身及其所属工作空间都必须在允许范围内。空列表表示没有对应访问权。获取工作空间访问权不会自动取得其中全部现有或未来项目。操作者在获授权工作空间创建项目后取得自己新建项目的访问权。

需求创建后固定项目归属，不能通过移动需求将历史正文暴露给其他项目。运行、事件、调用、上下文、检查点、模型工件、评审、候选、测试报告和交付导出继承运行所在项目的权限。检查点派生继续属于原项目，不能通过复用证据取得其他项目权限。角色、技能与 SOP 属于具体工作空间，关联和发布不得引用另一空间的资源。

账号、角色和授权修改由管理员处理。停用、密码轮换、注销和授权调整后的访问按当前状态检查，先前打开的页面或幂等请求结果都不会成为持续授权。系统不提供每项目不同角色、单独审批角色或逐字段自定义授权。

## 服务端检查

浏览器按当前能力显示菜单和按钮，服务端仍对每次请求独立鉴权。手工输入详情链接、直接发送 HTTP、替换项目或资源 ID、携带已保存的幂等键，都受同一规则约束。

列表先按权限及工作空间筛选，再分页和计算计数；总览、近期记录、审批及费用只使用同一授权集合。指定无权访问的工作空间、项目或对象时，服务端拒绝请求。成员无法依靠聚合数量、运行详情、内容摘要或旁路历史接口查看别人的数据。

修改操作在业务事务中复查权限、当前版本和依赖归属。Git、网关等准备工作之后再次核验，避免授权在准备期间撤销后仍提交。业务成功及其审计原子保存，拒绝和失败另记事实；同键重试只能在当前仍获授权时读取或复用已提交结果。

工作空间的 `endpoint_ids` 与 `repository_ids` 由管理员显式分配，空列表不开放任何模型或仓库。安装不预置可调用模型，管理员接入自己的端点及价目后，才授权给业务空间。准备、派发和恢复均检查当前授权端点及仓库，冻结旧计划不构成绕过空间策略的许可。

完整模型配置、可信仓库与套件配置、评估、成员和实例审计接口限管理员。执行者通过业务入口取得创建任务所需的受限选项，不能因此读取其他项目的探测运行或平台配置。完整审计导出保留实例全链和证明内容，按项目筛选不会将其转换为局部公开报告。

## 可复验操作

管理员先在“团队与设置”创建操作者和只读成员，显式选择工作空间及项目。可用两个隔离项目核对以下行为。

1. 新状态首次选择个人配对后，默认空间出现「我的项目」；使用管理员入口查看尚未配对的空实例时，该空间仍无业务项目。切换示例空间仅有一个项目和一条待配置模型的单任务，无需求、SOP 或人工关卡。再次启动，数量保持不变。
2. 操作者只获团队空间的项目 A，项目列表、总览、需求和运行都不出现项目 B 或示例项目。直接读取项目 B 及其运行证据被拒绝。
3. 只读成员获得项目 A，能从工作台、项目与任务读取内容、进展和证据。创建、修改、审批、派生和运行控制均无入口，直接请求写 API 也被拒绝。
4. 两种普通成员访问账号列表、模型管理、可信配置、评估和完整审计接口均被拒绝，不能通过菜单深链接绕过。
5. 成员先完成一项幂等写操作，管理员撤销项目授权。以原幂等键重试、刷新详情或读取工件均被拒绝，业务不重复提交。
6. 升级既有状态，确认原项目归属、运行 ID、候选 SHA 和审批继续保留，旧账号在分配授权前看不到业务内容。管理员可以核对迁移和授权审计。

以上为验收动作。自动化及浏览器的实际执行范围、结果和环境记录在[构建与运行](06-构建与运行.md)，不以示例页面状态替代回归结果。
