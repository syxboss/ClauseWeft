# ClauseWeft · 企业平台范围与验收基线

个人配对、Claude Code 修改和 DeepSeek Harness 只读评审的接口与边界见[个人工作台与外部 Agent](12-个人工作台与外部Agent.md)。下列历史基线用于校验原有运行及共享部署的兼容性。

产品版本 0.0.1 · 评审基线 v0.5 · 2026-11-25 更新。主线为“本地优先的可控 AI Agent 编排与软件工程工作台：提交目标，按需选模、调用工具与外部 Agent，交付结果与可核验证据”。默认采用创建项目、提交任务、查看结果的三步路径，需求、SOP、MCP 与审批按任务需要启用。[产品需求](01-产品需求.md) · [Harness 能力与审计](09-Harness能力与审计.md) · [后续演进与路线图](13-后续演进与路线图.md)

## 范围修正

| 议题 | 采用的产品要求 | 验收方式 |
|---|---|---|
| 执行主线 | 目标与内容进入任务，模型执行后回到结果和证据 | 无需建立需求或发布 SOP 即可完成普通任务 |
| 模型协作 | 自配模型、动态选模、独立评审和候选实测保留 | 普通选定模型可执行，高级自动路由与协作通过 A01–A11 |
| 按需流程 | 角色、技能和 SOP 支持重复工作，代码交付使用必要关卡 | 经“协作”维护模板，创建任务时可选择已发布的流程，既有代码交付门槛不被绕过 |
| 企业可靠性 | 服务端权限、版本、预算、恢复和审计贯穿执行 | 跨范围访问、迟到发布、重复结算和无效证据被拒绝 |
| 实际用量 | 根据接入模型的版本价目与实际回执统计 | 模型、配置版本、token、失败重试和币种可逐项核对 |
| 页面组织 | 主要入口围绕工作台、项目、任务和模型用量 | 默认任务先显示内容与结果，图编排和证据调试按需展开 |

## 简化路径与模型用量验收

| 编号 | 操作 | 通过条件 |
|---|---|---|
| S01 普通任务 | 在授权项目填写任意非空目标，选择自行接入的模型后提交 | 无独立需求、角色、SOP 和人工审批也能执行；结果与输入、模型、状态关联 |
| S02 默认页面 | 新安装进入团队空间，再查看任务创建与详情 | 主要入口清楚；“协作”与“资源与管理”按角色显示；普通结果先于节点图和原始证据显示 |
| S03 模型配置 | 未登记模型时打开工作台，管理员配置模型并授权给空间 | 无虚构模型、价目或调用；未授权模型不可选或派发；配置完成可提交任务 |
| S04 自动预算 | 对选定模型的单任务省略预算，再用不同币种及价目重复 | 服务端生成对应币种的有限单次预算，未假定固定美元额度，派发仍检查实际余额 |
| S05 版本计价 | 用同一模型分别按两个价格版本完成任务并读取用量 | 两个版本分别列出实际 token 与金额，更新价格不重写旧调用 |
| S06 未知与重试 | 完成正常、重试、失败、缺用量、非法用量和待核对调用 | 调用计数包含实际失败重试；缺失 token 不填零；待核对与已结算分列 |
| S07 币种与授权 | 两个模型使用不同币种，两个项目分别授权 | 按币种汇总且不自动换汇；所有模型用量只源于当前授权项目 |
| S08 研发执行保留 | 在没有自定义模板的项目直接选择内置代码交付，提供仓库、基准、套件及预算；另选择已发布协作，再返工、取消和恢复 | 内置代码交付不要求先设计 SOP；动态路由、独立身份、受限补丁、版本审批、必测证据及恢复契约继续通过 |
| S09 复杂任务 | 提交显式预算的复杂任务，分别返回有效与无效分工，用两个 worker 执行有效子任务 | 预览只含规划节点。分支可并行，各自成功后才解锁汇总。无效、重复或迟到的规划回执不会新增分支，每次实际调用均可对账 |
| S10 指定角色 | 在普通任务中选择同空间的角色并启动，之后修改角色，检查原运行请求，另提交冲突的模型绑定 | 原运行保留角色修订、提示、阶段、绑定与技能版本。用户输入和系统指令可分别读取。冲突提交被拒 |

这些条目定义复验动作，实际执行范围与结果以[验证记录](06-构建与运行.md)为准。

## 企业平台验收

以下条目定义验收动作，实际通过数、环境和未覆盖项见[验证记录](06-构建与运行.md)。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| P01 项目与需求 | 建立两个项目，分别新增需求，编辑优先级与状态，刷新并重启服务 | 数据持久化，筛选仅列出所选项目的业务记录，关联关系有效 |
| P02 模板发布 | 创建含模型和人工关卡的 SOP，编辑依赖并保存，再发布 | 草稿和发布版本可辨认。节点 ID 重复、悬空依赖、环被拒绝 |
| P03 模板执行快照 | 从已发布模板创建运行，再修改模板和角色 | 已有运行继续使用创建时的节点、提示和绑定，新运行使用新发布版本 |
| P04 人工关卡 | 上游完成后从审批中心打开人工关卡，读产物并批准 | 记录操作者和依据，依赖该关卡的节点继续执行，同键重试不重复批准 |
| P05 账号与权限 | 管理员创建 operator 和 viewer，分别登录，直接请求成员和业务写 API，再登出 | 权限由服务端落实，密码不出现在响应和审计中，登出的会话失效 |
| P06 真实总览 | 分别创建成功、待审批、失败或待核对运行 | 总览和用量可与运行、尝试及账本逐项核对，未知结果独立表示 |
| P07 审计追溯 | 新建和修改项目、角色、模板、成员，启动与处理运行 | 审计记录包含时间、操作者、动作和目标，业务事务失败另记失败结果，成功业务与成功审计原子提交 |
| P08 高级协作路径 | 打开“协作”，切换项目、建需求、编辑并发布 SOP、创建运行、处理审批、读产物 | 无脚本错误，错误与空态清晰，结构化表单可操作，窄屏可导航 |
| P09 旧状态升级 | 用包含端点、历史运行、候选与交付的旧状态目录启动新版本 | 历史能读取，原始候选标识保留，旧运行归入默认项目，新建需求可以发起关联运行 |
| P10 首次数据 | 在空目录启动，切换团队与示例空间，再重启 | 团队空间没有项目、需求与运行，示例空间仅一个项目及一条待配置模型的单任务，不初始化需求、SOP 或审批，不派发模型或伪造测试证据，重启不重复初始化 |
| P11 数据授权 | 新账号先不授权，再仅授权空间 A 的项目 A1，另准备 A2 与空间 B 的项目 | 空授权无数据，列表、分页、总览、审批和费用只使用获授权项目，直接读取其他项目及嵌套证据被拒绝 |
| P12 菜单与 API | 分别用 admin、operator、viewer 登录，直接请求管理菜单对应 API 与深链接 | 菜单和操作符合角色，普通成员不能访问账号、模型管理、可信配置、评估和完整审计，viewer 不能写业务对象 |
| P13 授权撤销与缓存 | 完成幂等写入后撤销项目授权，用原键重试并刷新上下文、工件及派生来源 | 重新核验当前授权，缓存与冻结快照不能绕过撤销，拒绝有审计且没有重复业务结果 |
| P14 迁移与引用 | 升级旧状态，再尝试跨空间引用角色、技能、模板或移动项目 | 数据和历史保留，非管理员不自动取得全实例权限，跨空间引用及迁移越权被拒绝 |

## Harness 能力与完整审计验收

| 编号 | 操作 | 通过条件 |
|---|---|---|
| H01 技能生命周期 | 新建、修改和停用技能，读取历史，再在角色与单任务中选择 | 历史版本可查，陈旧写入被拒绝，正文、修改身份和新旧版本可关联 |
| H02 上下文冻结 | 发布引用技能的模板，修改技能后分别启动旧发布版本与新版本，用本地技能固定云端 | 每次运行固定其实际技能版本和正文，后续编辑不改写历史，本地约束阻止云端派发 |
| H03 请求证据 | 派发含角色、技能、上游工件和返工意见的节点，再使其进入新世代 | 每个已派发尝试都能查询实际消息与内容摘要，旧请求保持可读并与原端点及输出上限绑定 |
| H04 检查点派生 | 在稳定单任务或 SOP 创建检查点后派生，再更改原运行；另对活动调用及仓库研发尝试派生 | 检查点和原运行独立，成果复用来源明确，新预算单独登记，人工关卡与其下游重新处理，未经支持的派生被拒绝并留审计 |
| H05 访问与决定 | 用有效成员读取内容、执行写入，再提交过期版本、非法正文和只读账号写入；尝试登录失败与注销 | 有身份、路径、结果和请求关联的审计记录，拒绝不冒充成功，登录密码与原始认证令牌不进入记录 |
| H06 运行证据 | 启动、暂停、恢复、返工、取消并处理迟到回执，查看模型产物与账本 | 后台事件能关联运行、节点、尝试、请求及产物，费用记录与已发生事件可核对，重复回执不重复发布 |
| H07 链校验与导出 | 校验记录链并按项目或运行筛选导出，在副本中修改或移除一条记录后重验 | 导出保留完整链和筛选命中范围，可离线复验，被改动的副本无法通过原基准校验，导出动作自身留访问记录 |
| H08 旧数据与配置 | 从旧状态启动 0.3，修改有效部署配置再启动，读取旧请求和历史审计 | 迁移来源和配置变化有记录，历史缺少的请求证据明确缺失，旧候选和决定保持可查询，链的受信边界写清 |

## 路由和可信交付验收

| 编号 | 给定与操作 | 通过条件 |
|---|---|---|
| A01 内容路由 | 登记便宜短上下文 A 与较贵长上下文 B，分别提交短长输入，禁用 B 重试 | 短输入选 A，长输入选 B，禁用后阻塞，理由显示上下文、价格及数据去向 |
| A02 数据边界与回退 | 仅本地任务固定云端，再对允许外发的任务注入可恢复限流 | 前者不外发，后者仅向预算内合格候选回退，每次尝试可查 |
| A03 模型身份与意图 | 提交“评估是否需要改代码”，给双评审组配置同模型别名 A/A2 | 单任务识别评审，别名不能凑齐独立模型，固定端点失败等待处理 |
| A04 并发与依赖 | 两个评审各等待另一路开始，批准需求前后检查实现派发 | 调用时间重叠、输入一致，未批准前无编码调用，必需分支失败阻止汇合 |
| A05 意见与基线 | 对同条款给出相反意见，修改权限来源并批准新稿 | 保留意见、裁决和版本，新稿重评后才能批准，旧审批无法推进新稿 |
| A06 冲突与重放 | 两个工作包修改同一行，选择或人工整合候选 C，再重放导出补丁 | 两份差异保留，冲突显式待处理，干净同基准重放得到同一代码树 |
| A07 版本失效 | C 已有通过报告后修订需求或产生 D，令 C 的回执迟到 | 历史保留，旧报告不能放行 D 或新需求，受影响下游按世代失效 |
| A08 预算竞争 | 余额 1.00，两路各需 0.70，同时派发，再重启未知结果的调用 | 最多一路预留成功，未知价格受硬预算阻止，已发调用保持可对账记录 |
| A09 恢复与取消 | A 成功、B 超时，从检查点重试 B，取消后返回迟到回执 | A 不重复派发，取消后无新执行或迟到产物发布，已收费项可对账 |
| A10 实测门槛 | 将必测项做错、删除、修复，再让执行器超时 | 依次为失败、缺项、通过、未完成，仅实测通过可交付，保存真实退出与输出证据 |
| A11 效果对照 | 冻结任务及允许模型，回放后执行固定和自动两侧并盲评 | 分别报告约束违规、缺测、通过数、含失败重试的成本与实际耗时，未知费用保持待核对 |

## 放行与记录

任务方式与计价按 S01–S10，平台、授权和可选高级能力按 P01–P14，Harness 与审计按 H01–H08，路由与仓库交付沿用 A01–A11。每条执行记录注明代码版本、配置版本、运行 ID、模型使用替身或真实服务、Docker 是否实际运行、通过与失败证据。文档中的验收设计与实际执行记录分别维护。

需求版本、候选提交、必测清单、镜像和账务均须可核对。未经有效审批的发布、缺少真实测试的交付通过、越出路径授权的补丁、预算竞争造成重复预留，均阻断对应功能放行。

新增技能或上下文来源后，实际模型请求和其证据必须对应同一份内容。检查点和派生运行不能继承原运行的人工授权。审计链校验失败、导出无法关联内容版本、认证凭据进入日志或旧数据缺失被显示为已验证，同样阻断相应验收。数据库拥有者的离线重写能力与外部封存策略按[审计边界](09-Harness能力与审计.md)判断。

## 后续部署验收

真实企业环境另需确定试点组织、自配模型与价目、数据范围及可核对的供应商账单。普通单任务不要求两个模型或 Docker；采用独立评审和仓库交付的团队再核验足够的独立模型、业务仓库与固定验收环境。SSO、组织目录、每项目独立角色与逐动作自定义授权、互不信任租户、分布式执行、代码托管提交、MCP 与其他编码 CLI 适配器分别建立验收计划。当前工作空间、项目显式允许列表和角色边界见[工作空间与权限](10-工作空间与权限.md)及[安全说明](../SECURITY.md)。
