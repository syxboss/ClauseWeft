# 构建与运行

平台包含企业研发协作 Web 工作空间、命令行和[独立 Gateway](../src/clauseweft/gateway/README.md)。两项服务在独立进程运行。

## 启动平台和运行验收

```bash
PYTHONPATH=src python3.11 -m clauseweft serve --config examples/workbench.json --state ~/.local/share/clauseweft
PYTHONPATH=src python3.11 -m unittest discover -s tests
```

默认使用路径为创建项目、提交任务、查看结果。管理员先在独立网关配置自己的模型，在平台登记币种、输入/输出价目并向工作空间授权。普通任务选择已配置模型后可直接执行，无需独立需求、SOP、审批或 Docker；未填预算时按模型配置计算有限的单次执行上限。“协作”提供需求与流程编排，仓库交付从“新建任务”的执行方式选择。[首次任务与模型用量](11-任务执行与模型用量.md)

模型目录、仓库配置、可选审批与导出操作见[工作台使用说明](../src/clauseweft/api/README.md)。源码测试默认启用本机 HTTP 替身、临时 SQLite 与 Git 仓库。指定本机已有 Python 容器镜像的不可变 ID，可同时复验隔离测试的失败、缺项、通过、超时，以及从 HTTP 建单到导出的完整流程：

```bash
CLAUSEWEFT_TEST_IMAGE="$(docker image inspect --format '{{.Id}}' python:3.11-slim)" PYTHONPATH=src python3.11 -m unittest discover -s tests -v
```

| 文档验收 | 可复现证据 |
|---|---|
| A01–A03 | 路由快照、HTTP 端点登记/启停、目录 ETag、网关协议、模型身份与回退规则，见 [路由](../tests/test_route_preview.py)、[执行](../tests/test_execution.py)和[网关](../tests/test_gateway.py)测试 |
| A04、A08、A09 | 双 worker 屏障、同一冻结输入、预算竞争、重启、取消及迟到回执，见[调度回归](../tests/test_execution.py) |
| A05、A07 | 基线审批、重评、阻断意见、陈旧候选与测试环境，见[决议](../tests/test_decisions.py)和[返工回归](../tests/test_delivery_actions.py) |

以上场景的模型答复由确定性替身提供。真实模型质量、供应商账单与业务仓库的验收条件，需在团队选定的真实端点与业务仓库验收。当前交付支持普通任务、按需多模型协作，以及保留交付门槛的代码研发流程。团队账号和项目承载权限与归属，独立需求、角色和 SOP 为可选复用能力。每个运行拥有有限预算，普通单任务可由服务端按模型计算，配对评估的执行量为每题两侧预算之和。当前阶段的增量恢复按实际节点依赖进行。

## 从源码试跑

在仓库根目录执行以下命令。运行时只使用 Python 3.11 及以上版本的标准库。macOS 上如有多套 Python，可把 `python3.11` 换成目标解释器的绝对路径。

```bash
PYTHONPATH=src python3.11 -m clauseweft doctor
PYTHONPATH=src python3.11 -m clauseweft modules
PYTHONPATH=src python3.11 -m clauseweft route --input examples/route-demo.json
```

需要安装为终端命令时，可在独立虚拟环境运行 `python -m pip install .`，再执行 `clauseweft doctor`。Windows PowerShell 可用 `$env:PYTHONPATH = 'src'` 后执行 `py -3.11 -m clauseweft doctor`。

| 命令 | 如何读结果 |
| --- | --- |
| `doctor` | `runtime_ok` 表示 Python 版本达到运行基线，并显示操作系统、架构和模块数。 |
| `modules` | 从静态登记表列出模块名与职责，可与 [概要设计](04-概要设计.md) 核对。 |
| `route --input FILE` | 读取 UTF-8 JSON 并输出路由理由。退出码 0 表示选中模型，1 表示无候选或需要补充输入，2 表示参数、文件或配置无效。 |

[示例快照](../examples/route-demo.json)包含一个本地评审模型和一个云端模型。当前任务要求数据仅留本地，预期结果为 `status=selected`、`intent=review`、`selected_endpoint=local-review`。云模型价格更低，也会因 `data_scope` 被排除。可复制文件再把 `models` 改为空数组，验证 `blocked` 和退出码 1。命令行中的 endpoint 是候选标识，预览仅计算选择结果。

## Docker 运行

准备好 Docker 引擎与 `python:3.11-slim` 基础镜像后，执行以下命令。首次获取基础镜像需要连接镜像仓库。

```bash
docker build --pull=false --network=none -t clauseweft:dev .
docker run --rm --network=none --read-only --cap-drop=ALL clauseweft:dev doctor
docker run --rm --network=none --read-only --cap-drop=ALL clauseweft:dev modules
docker run --rm --network=none --read-only --cap-drop=ALL clauseweft:dev route --input examples/route-demo.json
```

镜像的默认入口是 `python -m clauseweft`，默认子命令是 `doctor`，运行用户为 UID 65532。若要读本机配置，可将单个 JSON 文件挂载为只读，保证该 UID 可读。

```bash
docker run --rm --network=none --read-only --cap-drop=ALL \
  --mount "type=bind,source=$PWD/examples/route-demo.json,target=/input.json,readonly" \
  clauseweft:dev route --input /input.json
```

## 本机编译

在目标系统安装 Python 3.11+ 和 C 编译工具链，例如 macOS 的 Xcode Command Line Tools。以下示例使用全新的构建环境。编译工具属于构建时依赖。

```bash
python3.11 -m venv .venv-native
.venv-native/bin/python -m pip install Nuitka==4.3.5 ordered-set==4.1.0 zstandard==0.25.0
.venv-native/bin/python scripts/compile_native.py
./dist/native/launch_clauseweft.dist/clauseweft doctor
./dist/native/launch_clauseweft.dist/clauseweft route --input examples/route-demo.json
.venv-native/bin/python scripts/check_distribution.py native
```

Nuitka 的 standalone 模式将 Python 模块编译为本机代码，随程序一起分发运行库。交付时复制完整的 `dist/native/launch_clauseweft.dist/` 目录，入口为其中的 `clauseweft`，Windows 对应 `clauseweft.exe`。操作系统和 CPU 架构改变时，应在对应目标上构建并运行检查脚本。

## 交付范围与验收

平台围绕任务内容、模型执行、产物和真实用量组织。首次个人配对会准备所有者和默认项目。共享部署可从管理员入口进入，配对前的新团队空间为空，独立示例空间仅一个项目与一条待配置模型的单任务，不创建需求、SOP 或人工审批。初始化不调用模型或容器，重启不重复生成。管理员在团队设置中创建账号并分配工作空间及项目范围，新账号默认无业务数据授权。账号密码经 scrypt 哈希保存，登录会话保留 12 小时，停用成员或轮换密码会撤销其会话。执行者在授权范围内维护研发资源和运行，只读成员不能写业务数据，完整管理与审计接口仅管理员。

## 本机真实模型的多步目标验收

先启动本机 Ollama，确认要采样的模型已经安装。在仓库根目录运行以下命令，可将模型名替换为本机的标签。

```sh
python3.11 scripts/check_agent_goals.py --model llama3.1:latest --repeats 2 --max-retries 1
python3.11 scripts/check_agent_goals.py --model llama3.1:latest --mode auto --repeats 2 --max-retries 1
```

脚本在临时目录创建工作台状态，并经独立的回环网关调用 `127.0.0.1:11434`。默认 `conditional` 模式提交显式查重约束。`auto` 省略 `requirement_query`，工具调用顺序由模型选取。两种模式使用相同的目标、审批条件和评分。每轮创建三个独立项目，分别验收命中已有需求、查无记录后创建需求、拒绝新建需求。自动审批仅用于这批合成目标，按步骤检查查重词、新建标题、优先级和验收描述。模型自己提出工具调用并依据实际回执回答。

每个样本通过 `GET /api/v1/runs/{id}/goal-assessment` 取回判定。标准输出逐行记录判定、未满足的条件和重试数，最后给出各场景及整体的通过数和总数。卡在审批、模型格式或回执的样本也计入分母。默认每个样本执行一次；`--max-retries 1` 允许对已知格式或步骤错误额外重试一次。所有样本均通过时退出码为 0。临时项目按零单价登记本机模型，适合核对行为与实际 token 调用。
