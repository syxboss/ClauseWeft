# ClauseWeft · 后续演进与路线图

产品版本基线 `0.0.1`（当前分支已落地 P0 + P1 全部能力）· 2026-11-25 更新。本文档记录 ClauseWeft 的能力演进清单、模块落点与设计约束。[产品需求](01-产品需求.md) · [验收基线](02-需求评审.md) · [概要设计](04-概要设计.md)

## 设计原则

所有后续能力均须保持 ClauseWeft 的核心工程契约，不以牺牲可控性与可核验性换取功能堆叠：

- **服务端权限边界**：工作空间、项目与角色授权始终在服务端核验，授权撤销立即生效。
- **预算与循环硬上限**：每次推理派发前预留预算，所有自主反思、工具步数与跨 Agent 委托均设有界上限。
- **可复现与离线审计**：输入快照、模型版本、单价、真实 token、测试报告与人工决定同事务提交并纳入可离线校验的哈希审计链。
- **零第三方运行时核心**：Python 核心运行时继续保持标准库实现，重型或特定供应商能力通过隔离容器、独立网关或显式插件适配器接入。

## P2｜运行中交互、多端协同与工程闭环（目标版本 `0.3.0+`）

### P2-1｜运行中待发提示队列、中途纠偏与动态重规划
- **目标**：引入运行中待发提示队列（Pending Prompt Queue），支持在长运行任务期间排队补充指示、重排/编辑/取消队列项，由服务端在下一节点世代安全注入；`complex` 模式支持部分分支失败后的局部重规划或降级汇总选项。
- **涉及模块**：`runs/`、`workflow/`、`api/run_routes.py`、`api/web/scripts/`
- **核心约束**：中途注入指令记入运行事件与审计链，不篡改已派发尝试的冻结请求上下文；支持通过已落地的 SSE 接口实时推送进度。

### P2-2｜可复用多模型协作模式与独立首轮评审
- **目标**：将多模型独立首轮评审（避免观点污染）、顺序链（`/chain`）、扇出并行（`/fan`）与交叉质证（`/verify` / Roundtable）抽象为开箱即用的轻量协作模式，支持发言顺序、轮次上限与暂停/继续控制。
- **涉及模块**：`workflow/`、`api/run_planning.py`、`api/web/scripts/workflows.js`
- **核心约束**：独立评审模式继续由服务端校验底层 `model_identity` 去重，确保同一底层模型别名不能互审。

### P2-3｜定时 / Cron 自主任务（Scheduled Runs）
- **目标**：支持在工作台配置一次性或 Cron 周期任务（如每日依赖安全扫描、定时回归检查、周期汇总报告），宿主在线时自动派发，客户端关闭不影响执行。
- **涉及模块**：`api/platform.py`、`runs/`、`api/agent_jobs.py`、`storage/`
- **核心约束**：每个定时计划必须绑定固定单次预算上限、显式项目授权与只读/审批策略；创建者撤权或项目归档后自动停用并写入审计。

### P2-4｜容器网络出口白名单代理（Egress Allowlist Proxy）
- **目标**：为外部 Agent 容器提供可选的轻量级本地出口代理，仅放行明确配置的供应商域名（如 `api.anthropic.com`、`api.deepseek.com`），收紧目前 [SECURITY.md](../SECURITY.md) 中标注的 Docker bridge 出站网络边界。
- **涉及模块**：`agent_runtime/container.py`、`agent_runtime/config.py`
- **验收要点**：在容器测试中验证允许域名可通、未授权外联域名与内网地址均被拒绝。

### P2-5｜Agent 轨迹级评测基准与 OpenTelemetry 可观测性
- **目标**：在现有路由回放、盲评与 3 场景需求验收（`evaluation/`）之上，补充 Agent 轨迹指标（工具选择准确率、平均步数、自动修复通过率、单成功任务成本分布）及标准 OpenTelemetry（OTel）Trace 导出。
- **涉及模块**：`evaluation/`、`audit/`、`usage/`

### P2-6｜受控 Git 托管闭环、移动远程接入与多机 Worker 演进
- **目标**：
  - **Git 托管闭环**：交付清单经人工接纳后，支持受控创建本地分支或经二次审批推送并创建 GitHub/GitLab PR（自动附带测试报告与审计摘要）。
  - **安全移动远程接入**：提供基于 Tailscale 或受控反向代理的远程访问配置指南与短效配对码流程，方便手机端随时审批工具调用、验收补丁与查看 SSE 进度。
  - **多机 / 跨 Agent 协作演进**：未来扩展跨机 Worker 与多 Agent 互相委托时，采用接收方按方向显式授权、跳数上限（如 3 跳）、速率限制与幂等 `request-id` 队列，确保跨机协作同样可追踪、防死循环；企业大团队部署可按需演进 OIDC/SSO 与 PostgreSQL 后端。
